# Form Submission Proxy — Design Spec

**Date:** 2026-05-23

## Goal

Two distinct capabilities:

1. **CLI** — Given a public Google Form URL, output a JSON Schema (Draft 2020-12) describing the form's fields, types, and validation rules. Optionally write a `FormDefinition` file for use by the Worker.
2. **HTTP API (Cloudflare Worker)** — Accept `POST /api/v1/forms/:formId/responses`, validate the JSON body against the form's schema, and submit a response to Google Forms.

---

## Architecture

### Developer workflow (before deploy)

```
1. tsx scripts/gen-field-mapping.ts --url <viewform_url> --out src/forms/<formId>.json
2. Add import to src/forms/registry.ts
3. pnpm deploy
```

### Runtime (Cloudflare Worker)

```
POST /api/v1/forms/:formId/responses
      │
      ├─ Look up FormDefinition from static registry
      │   → 404 if formId not registered
      │
      ├─ Validate request body against JSON Schema
      │   → 400 + structured error details if invalid
      │
      ├─ Map field keys → entry.XXXXXXX IDs
      │
      └─ POST application/x-www-form-urlencoded to Google Forms
          → 200: { "success": true }
          → 502 on upstream failure
```

`GET /schema?url=...` and `POST /schema` (existing endpoints) are retained for developer tooling.

## Data Structures

### FormDefinition file (`src/forms/<formId>.json`)

Generated by CLI, bundled statically into the Worker at deploy time.

```json
{
  "formId": "1FAIpQLSabc123",
  "submissionUrl": "https://docs.google.com/forms/d/e/1FAIpQLSabc123/formResponse",
  "schema": {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object",
    "additionalProperties": false,
    "required": ["full_name"],
    "properties": {
      "full_name": { "title": "What is your name?", "type": "string", "minLength": 1 },
      "age":       { "title": "Your age", "type": "integer", "minimum": 0 },
      "color":     { "title": "Favourite color", "type": "string", "enum": ["Red", "Blue"] }
    }
  },
  "fieldMap": {
    "full_name": "entry.826300186",
    "age":       "entry.1817991179",
    "color":     "entry.267916828"
  }
}
```

**Key decisions:**
- `fieldMap` keys match `schema.properties` keys exactly — deterministic `field_N` without Gemini, snake_case with Gemini (CLI decides at generation time).
- `schema` property `title` stores the original question text (not the entry ID — that moves to `fieldMap`).
- `submissionUrl` is stored directly; Worker never constructs it.

### TypeScript interface (`src/lib/types.ts`)

```typescript
export interface FormDefinition {
  formId: string;
  submissionUrl: string;
  schema: Record<string, unknown>;
  fieldMap: Record<string, string>;  // schemaKey → "entry.XXXXXXX"
}
```

### Static registry (`src/forms/registry.ts`)

```typescript
import form1 from './1FAIpQLSabc123.json';

const registry = new Map([
  ['1FAIpQLSabc123', form1 as FormDefinition],
]);

export default registry;
```

One import + one Map entry per form. Developer adds these manually after running the CLI.

## Components

### `src/lib/validator.ts` (new)

Validates a plain JSON object against the subset of JSON Schema keywords that our schema generator produces. No external library — purpose-built for our output.

**Supported keywords:**
`type`, `required`, `enum`, `const`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `format` (email, uri), `pattern`, `minItems`, `uniqueItems`, `allOf`, `not`, `anyOf`

**Interface:**
```typescript
export interface ValidationError {
  field: string;
  message: string;
}

export function validate(
  data: unknown,
  schema: Record<string, unknown>,
): ValidationError[];
// Returns [] on success, array of errors on failure
```

**Error response (400):**
```json
{
  "error": "Validation failed",
  "details": [
    { "field": "age", "message": "must be >= 18" },
    { "field": "email", "message": "must match format: email" }
  ]
}
```

### `src/lib/submitter.ts` (new)

Encodes validated data as `application/x-www-form-urlencoded` and POSTs to Google Forms.

**Interface:**
```typescript
export class SubmissionError extends Error {
  constructor(message: string, public readonly statusCode?: number) { ... }
}

export async function submitToGoogleForms(
  submissionUrl: string,
  fieldMap: Record<string, string>,
  data: Record<string, unknown>,
): Promise<void>;
// Throws SubmissionError on failure
```

**Encoding rules:**
- String/number/integer: `entry.XXXXXXX=<urlencoded_value>`
- Array (checkboxes): repeat the same entry ID — `entry.XXXXXXX=A&entry.XXXXXXX=B`
- Missing optional fields: omit from body entirely

### `src/index.ts` — new route

```
POST /api/v1/forms/:formId/responses
```

Handler logic:
1. Look up `formId` in registry → 404 if not found
2. Parse request JSON body → 400 if malformed
3. `validate(body, definition.schema)` → 400 + details if errors
4. `submitToGoogleForms(definition.submissionUrl, definition.fieldMap, body)` → 502 on failure
5. Return `{ "success": true }` with 200

### `scripts/gen-field-mapping.ts` — CLI changes

New `--out <path>` flag. When provided:
- Writes a `FormDefinition` JSON file to the given path
- Prints instructions for updating `src/forms/registry.ts`

Without `--out`, existing behavior unchanged (JSON Schema printed to stdout).

### `src/lib/schema.ts` — minor change

New export:
```typescript
export function buildFieldMap(
  fields: FieldDetail[],
  metas: FieldMeta[],
): Record<string, string>;
// Returns { schemaKey: "entry.XXXXXXX" }
```

Also: the `buildFieldPropertySchema` function changes `title` from the entry ID to the question text (`field.question`). The entry ID moves to `fieldMap` only.

## Error Handling Summary

| Scenario | HTTP Status | Response |
|----------|-------------|----------|
| `formId` not in registry | 404 | `{ "error": "Form not found" }` |
| Request body is not valid JSON | 400 | `{ "error": "Invalid JSON body" }` |
| Schema validation fails | 400 | `{ "error": "Validation failed", "details": [...] }` |
| Google Forms submission fails | 502 | `{ "error": "Failed to submit to Google Forms" }` |
| Unexpected error | 500 | `{ "error": "Internal server error" }` |
